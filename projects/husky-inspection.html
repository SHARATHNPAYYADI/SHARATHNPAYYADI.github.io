📌 Overview

Built an autonomous inspection stack for a Clearpath Husky UGV that patrols a set of waypoints (e.g. fire extinguisher checkpoints), captures images at each stop, runs a vision check for presence/absence, and auto-generates an HTML inspection report — all driven from a browser dashboard talking to a FastAPI + ROS2 bridge over REST and WebSockets. The dashboard supports both manual joystick teleop and fully autonomous multi-waypoint missions.

🔄 Mission Pipeline

Selecting waypoints and hitting START INSPECTION drives the full sequence end-to-end.

🧭 Navigate
Nav2 drives to each selected waypoint in sequence
→
📷 Capture
Camera service grabs an image at the waypoint
→
🔍 Inspect
Vision check classifies presence/absence of the target object
→
📝 Report
Once all waypoints are processed, an HTML report is generated automatically

⚙️ Key Engineering Decisions

1
Thin FastAPI bridge over a ROS2 core
Rather than exposing ROS2 directly to the browser, a FastAPI service wraps ROS2 service clients/subscribers and re-exposes them as plain REST + WebSocket endpoints — keeping the dashboard framework-agnostic and easy to iterate on independently of the robot stack.
2
Sequenced multi-waypoint missions, not one-shot goals
A dedicated start_mission_sequence service accepts an ordered list of waypoints and drives navigate → capture → inspect per point, publishing incremental mission_results so the dashboard can render progress live instead of waiting for the whole mission to finish.
3
Auto-generated report on mission completion
The backend tracks how many results have come back against the expected waypoint count; once they match, it fires an internal report generator that fills an HTML template with per-point images and found/missing status — no manual "generate report" step needed.
4
Real-time teleop over WebSocket, control over REST
High-frequency joystick velocity commands go over a persistent WebSocket straight to /cmd_vel for low latency, while lower-frequency actions (go-to-goal, capture, start/stop mission) use simple REST calls — matched to how often each actually needs to fire.
