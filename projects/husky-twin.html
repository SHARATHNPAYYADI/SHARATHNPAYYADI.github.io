📌 Overview

A single-robot, browser-native 3D digital twin of a warehouse Husky — real-time tracking, multi-stop routes, live obstacle replanning, a configurable warehouse layout editor, persistent run history with a metrics dashboard, and an onboard robot camera feed. No ROS, no physics simulator: a deterministic Python asyncio tick loop synced live to a React Three Fiber scene over WebSocket.

🔗 REST API

Alongside the primary /ws WebSocket channel, the backend exposes:

Route What it does
GET /health Liveness check
GET /runs?limit=50 Run history, newest first
GET /runs/stats Aggregate stats for the metrics dashboard
GET /runs/{run_id} A single stored run report
GET /layouts Saved layout summaries
GET /layouts/starter A freshly generated layout, to seed the editor
POST /layouts Save a new layout
POST /layouts/{id}/activate Hot-swap the running sim onto a saved layout — no redeploy needed

⚙️ Key Engineering Decisions

1
No ROS, no physics engine
A deterministic asyncio tick loop plus a hand-rolled 8-directional A* pathfinder is enough to demonstrate real-time tracking, replanning, and multi-stop routing — without the deployment overhead of a full ROS/simulator stack.
2
Hand-mirrored schema, no codegen
backend/app/schema.py (Pydantic) and frontend/src/schema/types.ts are kept in sync by hand as the single source of truth for the WebSocket wire format — simple enough for a solo project to maintain without a codegen pipeline.
3
Two independent 3D views
The Robot Cam is a second, always-streaming onboard/CCTV-style React Three Fiber view, kept fully independent from the main interactive scene so it never interferes with placing obstacles or planning a route.
4
Hot-swappable layouts without a redeploy
POST /layouts/{id}/activate lets the layout editor push a saved warehouse layout onto the live running simulation, so different scenarios can be tried without restarting the backend.
5
Free-tier deployment, kept warm deliberately
Backend on Render's free tier (ephemeral filesystem, so run history resets on restart) is pinged every 14 minutes by a scheduled GitHub Action so it never spins down from inactivity; frontend on Vercel talks to it over a single VITE_WS_URL env var that also derives the REST base URL.

📊 Results

  • Real-time robot tracking and live obstacle replanning rendered entirely in-browser, no native client needed
  • Configurable warehouse layout editor that hot-swaps the running simulation without a redeploy
  • Persistent run history and an always-visible metrics dashboard (totals, averages, per-day and per-obstacle-type charts)
  • Deployed end-to-end on free-tier infrastructure (Render + Vercel) with a keep-alive workflow to avoid cold starts

🔮 Future Work
