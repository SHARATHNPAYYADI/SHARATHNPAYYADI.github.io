📌 Overview

Built a complete autonomous navigation and pick-and-place stack for the idealworks iw_hub AMR, simulated in NVIDIA Isaac Sim and driven entirely through ROS2 Humble + Nav2. A single service call sends the robot to a dolly, lifts it with a velocity-ramped scissor joint, carries it across a mapped warehouse-style environment, drops it off, and clears itself — all controllable from a browser dashboard over rosbridge.

🔄 Mission Pipeline

One /mission service call drives the full sequence end-to-end.

🧭 Navigate
Nav2 NavigateToPose to the pick-up waypoint
→
⬆️ Lift
Scissor joint ramps up smoothly to grab the dolly
→
🚚 Transport
Nav2 drives to the destination waypoint carrying the load
→
⬇️ Lower
Lift ramps down to release the dolly
→
↩️ Clear
Straight-line retreat via direct /cmd_vel, bypassing Nav2

🔗 ROS2 Packages

Package Role
iw_hub_navigation Nav2 bringup — SLAM/AMCL localization, costmap and planner params tuned for the dual-lidar diff-drive base
iw_hub_lift_control Velocity-limited lift joint control — ramps the scissor lift instead of snapping to a target position
iw_hub_pick_place_msgs Custom RunMission service definition (ament_cmake)
iw_hub_pick_place_executor On-demand pick-and-place mission service — orchestrates navigate → lift → transport → lower → clear
frontend/iw_hub_console.html Standalone browser dashboard — triggers missions and shows live lift/pose telemetry over rosbridge

⚙️ Key Engineering Decisions

1
Map from geometry, not driving
Since the full environment already exists as a USD stage, the map was generated with Isaac Sim's built-in Occupancy Map tool instead of SLAM — projecting the geometry directly into a 2D grid. The tool's Z-slice range was set to bracket the lidar's mounted height so the exported map matches what the real 2D scan detects.
2
Dual-lidar costmap, single-lidar localization
Front and rear RPLidar S2E scans both feed the costmap as separate obstacle sources, but AMCL localizes off the front lidar only since it can't fuse two scan topics.
3
Velocity-ramped lift, not a position snap
Commanding /joint_command directly snaps the lift straight to target. lift_ramp_node instead steps the commanded position toward the target at a bounded velocity (default 0.01 m/s), publishing at 50 Hz for smooth motion.
4
Reduced turning speed to stop the dolly sliding
The dolly rests on the lift platform via friction only — no rigid joint. max_vel_theta/acc_lim_theta were reduced below Nav2 defaults, and PhysX static/dynamic friction between the platform and dolly was raised, to stop it sliding crooked mid-transport.
5
Bypassing Nav2 for the final clear-out
The dolly isn't sensed by the lidars as a costmap obstacle, so the next mission's path could clip it mid-turn. The final "drive straight clear" step bypasses Nav2 entirely — a direct /cmd_vel publish with distance tracked via /odom — to guarantee dead-straight retreat.

📊 Results

  • Full pick-and-place mission executed end-to-end from a single ROS2 service call
  • Stable Nav2 localization and path planning on a dual-lidar diff-drive AMR in Isaac Sim
  • Smooth, jerk-free lift transitions that keep an unsecured dolly stable during transport
  • Live browser dashboard for mission triggering and telemetry, with a simulated mode for UI testing without a live stack
