📌 Overview

Developed a complete autonomous pick-and-place pipeline for the PAL Robotics TIAGo Steel — a 12-DoF indoor service robot. The system integrates computer vision (ArUco marker detection), probabilistic grasp planning via spherical grasp sampling, MoveIt-based collision-aware motion planning, and Octomap-driven environment mapping. The pipeline was validated in both Gazebo simulation and on the physical TIAGo robot at the H_Da robotics lab.

⚙️ Execution Walkthrough

1
Service Initialisation
ROS service /pick_gui is called. All nodes subscribe to required topics; TF tree and robot state publisher come online.
2
Pre-Grasp Position
Arm moves to a singularity-safe pre-grasp configuration defined in the YAML file, verified in RViz.
3
ArUco Detection & Pose Estimation
Head scans across its full DoF range. The /aruco_single node detects the marker ID, then OpenCV computes the 6-DoF pose. Axes overlaid in RViz confirm detection.
4
Octomap Refresh
The previous Octomap is cleared and rebuilt with the current table and cube geometry, including exact height and collision properties, ensuring no stale obstacles remain.
5
Spherical Grasp Sampling
A sphere of candidate grasp approach vectors is generated around the cube. The highest-probability direction that avoids singularities is selected and passed to MoveIt.
6
Pick Execution
MoveIt computes a collision-free trajectory using OMPL. The arm approaches, gripper closes around the cube, and the robot lifts to the transport pose.
7
Place & Retract
The goal position (defined in YAML) is sent to MoveIt. The arm places the cube back at its original location, holds for 5 seconds, then retracts to safe pose.

🧠 Technical Approach

  • ArUco Markers: Binary square fiducial markers (6×6 dictionary) used for robust, rotation-invariant object detection. Single-marker pose estimation provides the 6-DoF grasp target with minimal compute.
  • Octomap Integration: Point cloud from the RGB-D camera feeds the Octomap occupancy grid. The grid is rebuilt after every detection cycle so the collision world always reflects the current scene.
  • Spherical Grasp Sampling: Instead of a fixed grasp direction, a probability distribution of approach vectors is generated. The arm approaches from the direction with highest grasp success likelihood, avoiding joint-limit and singularity regions.
  • MoveIt + OMPL: OMPL plans collision-free joint trajectories accounting for the Octomap, self-collision, and attached objects. Velocity and acceleration constraints are enforced via the joint_limits.yaml file.
  • YAML-Driven Configuration: Pre-grasp poses, goal positions, and arm joint limits are all externalised in YAML — making the pipeline adaptable without code changes.

🔮 Future Work

  • Replace MoveIT joint-space planning with MoveL (linear Cartesian paths) to reduce unnecessary arm twist during approach
  • Replace ArUco with deep-learning-based object detection (e.g. YOLOv8 + 6-DoF pose estimation) for marker-free grasping
  • Integrate mobile base navigation so the robot can fetch objects from arbitrary positions in the room
  • Dockerise the full stack for reproducible deployment across lab machines
  • Combine obstacle avoidance with path planning for on-the-go evade-and-navigate behaviour
